# Contributing

Thanks for looking. Open an issue before a large change so we can agree on the
shape; small fixes can go straight to a pull request.

## What this repository decides

Almost nothing. The portal is a client of the platform backend, which is the
only authority for authorization, tenancy, ownership, and money. If your change
is about who may do what, or about a balance, it belongs in the `open-giftcard`
repository instead.

What lives here is the staff-facing interface and the browser security boundary.

## Getting a working copy

You need .NET 10, Node 24, pnpm 11.9, PostgreSQL, and a running backend.

```bash
dotnet restore GiftCardPortal.slnx
cd src/GiftCardPortal.Web && pnpm install --frozen-lockfile
```

Create the portal's own session database and role as the README describes, set
`ConnectionStrings__Portal` and `Backend__BaseUrl`, then run the BFF and
`pnpm run dev` in two terminals.

The portal keeps its own database. It stores sessions only; it never holds
business data.

## Running the tests

```bash
dotnet test GiftCardPortal.slnx -c Release        # BFF
cd src/GiftCardPortal.Web && pnpm test            # frontend
```

The Playwright suite needs the backend checked out at the pinned commit with a
clean tree, plus PostgreSQL. `scripts/Run-PortalE2E.ps1` orchestrates it and
resolves `psql`, `node`, and `pnpm` from `PATH`, overridable with `PSQL_PATH`,
`NODE_BIN`, and `PNPM_BIN`. It does not run in CI.

## Common changes

### Adding a screen or a call

The backend client is generated by NSwag at build time from
`contracts/backend.openapi.json`. Do not hand-edit generated code and do not
hand-edit the contract: it is a captured copy of what the backend serves, and
its value is that it is faithful.

To bind an endpoint the pin does not yet contain, the contract must be
recaptured at an agreed backend commit, updating the recorded commit and hash in
`contracts/README.md` together. CI fails when the declared hash is not the hash
of the file beside it, so a half-done recapture cannot merge.

### Anything touching sessions or CSRF

Read [SECURITY.md](SECURITY.md) first. Backend tokens are held server-side and
encrypted; the browser gets one opaque cookie. Mutating `/bff` requests require
a matching `Origin` and a valid antiforgery token, and a missing `Origin` is
refused deliberately rather than treated as same-origin.

`DeploymentSafetyTests` asserts the application refuses to start outside
Development with insecure or non-`__Host-` cookies. If a change makes that test
fail, the change is wrong.

### User-facing text

English strings are also the i18n keys. Changing a sentence changes its key, so
`src/i18n/turkish.ts` must be updated in the same commit or the Turkish
translation silently falls back to English. `turkish.test.ts` guards both
directions and will fail on a missing or orphaned key.

### Brand and colour

Colour lives in the `@theme` block in `src/styles.css` and is compiled by
Tailwind, so changing it needs a rebuild rather than a runtime override. Brand
indigo measures 2.34:1 on white and is a surface and mark colour only, never
text; action indigo is 6.48:1 and carries links, focus, and primary actions.
Keep those roles if you change the palette. ADR-P002 records why.

## What a good pull request looks like

Behavioural changes carry tests. The build treats warnings as errors, and CI
runs format, lint, typecheck, the frontend suite, and the BFF suite.

Report results honestly, including anything you could not run.
